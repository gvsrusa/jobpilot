# JobPilot AI 0.4.0

External AI backends, all optional and all behind consent. Status: not published; builds are unsigned. This is a personal, non-commercial app. The owner waived AI subscription-policy and provider-terms concerns, including the release re-read of provider terms. The security controls (untrusted job text, no tools, consent records, validated output, no invented qualifications, no inferred work authorization) were not waived.

Placeholders named `PLACEHOLDER_...` are filled by the controller from a real run or a CI run. Nothing in this note was written from a run that did not happen, and a placeholder that is still there means the run did not happen yet.

## What was built

- **Hosted API providers** (FR-3.15 to FR-3.19) on your own key: OpenAI, Anthropic, Google (paid key), and OpenRouter. Each is off until you add a key, type a model id, and consent. Chat Completions for OpenAI, OpenRouter, and the endpoint; the Messages API for Anthropic; `generateContent` for Google. No request carries a tool, a search option, or a key in a URL. Hosted calls go only to the four vendor hosts over HTTPS with the operating system's TLS (Schannel, Security.framework), no proxy, and no redirect.
- **A loopback endpoint.** One address you name (`jobpilot ai endpoint`, or the AI screen), `http` and loopback only, no credential or query in the URL. It counts as external, because a proxy on a loopback port can forward: it needs consent, and it refuses `:cloud` and `-cloud` models. Changing the address suspends its consent and drops its key.
- **Keys.** Stored in the OS credential store as `ai-key-<name>` and nowhere else. In the app, a button makes Rust read the clipboard, show a native dialog naming the provider and the key's last four characters, store the key, and clear the clipboard; the webview sends only a provider name. In a terminal, `jobpilot ai key set <provider>` reads a hidden prompt or one line of piped stdin, and it is refused in the panel. The generic secret commands refuse the `ai-key-` prefix.
- **Gemini CLI adapter** (FR-3.10). Optional, off by default, on the installed CLI's own sign-in. It runs with every tool denied (a deny-all policy file on two flags, extensions and MCP off, hooks and sandbox off), the prompt on stdin, in an empty folder, with a run-time guard that fails the attempt on any tool event or any line it does not know, and a version floor of 0.40.0. Declared `no_tools`, so it handles job text.
- **Codex CLI adapter** (FR-3.11). Present and inert. It declares `StructuredOutput` only, because no OpenAI page documents a way to remove `apply_patch`. Every task needs `no_tools`, so every task skips it and no child starts. The AI screen says "No task can use this yet: it cannot prove it has no tools."
- **Consent for the new backends.** Per provider and sign-in method (`openai/api_key`, `anthropic/api_key`, `google/paid_key`, `openrouter/api_key`, `endpoint/loopback`, `gemini_cli/cli_login`, `codex_cli/cli_login`). A record holds the register row's text (migration 0012), so a changed row suspends it without a write. `google/paid_key` and `gemini_cli/cli_login` need an attestation that the key or sign-in is not a free Gemini one: no attestation, no record, no call. The consent screen shows the vendor's data use and "Show exactly what will be sent", the real prompt for the newest pasted posting.
- **Retries on hosted providers** (decision 11). One retry on 429, 503, or 529, only when `Retry-After` gives whole seconds, at most 30. No header, a date form, or a longer wait ends that provider with `rate_limited`. Timeouts, network errors, other 5xx, and quota errors never retry. This replaces the old "external providers retry validation only" rule in the AI providers spec.
- **CLI and screen.** `jobpilot ai key|model|endpoint|cli-path|consent show|give|revoke|enable|disable|order`, and the AI screen, now headed "AI providers". Refused in the terminal panel: the commands that take a key, change what runs, or give consent. `claude` stays the only CLI session the panel allows.
- **Memory refresh states its true ceiling.** `external_calls` is the pending questions times the external providers that could take each, because a failed reply goes on to the next provider. The dialog and the CLI text say that number, with the 20-question limit given separately.
- **CI.** A `TLS handshake` step on macOS and Windows runs the ignored `real_tls_handshake` test: an unauthenticated `GET` with no body to each of the four vendor hosts, any HTTP status passing. It is the Schannel proof and costs nothing. `--skip real_gemini --skip real_tls` keeps both out of the keychain steps.
- Migration 0012. Schema version 12. A 0.3 database (version 11) upgrades after a `pre-migrate-11-*` snapshot. Version 0.4.0.

## Not exercised

Unless a Task 11 row above says otherwise:

- **Every hosted API, with a real key.** The five wire shapes (request bodies, reply shapes, finish names, error bodies) were written from the vendors' documents and checked against local fakes only. Whether the real services accept the requests, and whether a real non-streaming reply always sends a stop reason (a missing one now fails as `bad_reply` on the Anthropic and Google wires), are unproven.
- **Google's bad-key reply.** A 400 holding `API_KEY_INVALID` reads as `auth_failed`. That body is known only from forum sources, not from Google's documents, and no real key has produced it.
- **The real Gemini CLI.** Nothing started a real `gemini`. The stream shape, exit 41, the error classes, and `GEMINI_SANDBOX=false` come from reading the installed 0.40.0 bundle and Google's docs. The `\@` escape rests on source reading. `real_gemini_has_no_tools_smoke` is the check and is ignored by default. The CLI's info notes go to stdout with no newline ("Using AI Credits..."); if they glue to the JSON they fail closed as `bad_reply`, and only a real run shows whether known notes must be stripped.
- **The real Codex CLI.** Inert, and its run path and flags are unverified. They need checking before the first task that qualifies.
- **Native dialogs and the clipboard.** The key dialog, the consent dialog, the refresh dialog, and the clipboard read and clear were driven through test harnesses with stubs. No person drove them in a real window on either system, and the real clipboard body is `cfg(not(test))`.
- **The TLS floor.** `tls_version_min` has no local test. Only `real_tls_handshake` covers it.
- **Windows at runtime outside the CI run.** The real CLIs and the GUI on Windows, `gemini.cmd`, policy path handling, and the clipboard plugin on WebView2.
- **A real model against the injection corpus.** The hosted corpus run uses scripted replies, as in earlier releases.
- x86_64 macOS, and the installers.

## Outstanding risks and parked items

Rulings made during the build, each a deliberate cost:

- **Gemini CLI has no transcript off switch.** The CLI records the full prompt under `~/.gemini/tmp/<id>/chats`, for 30 days by default, in 0.40.0 and on main. Moving it needs `GEMINI_CLI_HOME`, which moves the sign-in too. It is disclosed in the consent text through the register row, so a record given before that text is suspended. Cost: a posting sent through it sits on disk in plain text.
- **`GEMINI_SANDBOX=false` and the stream shape are unproven until a real run.** The adapter sets the variable (a value in the process beats any `.env`) and fails closed if it was already set. If the real CLI prints anything outside the known events, every run ends `bad_reply`.
- **Every `@` in a Gemini prompt is sent as `\@`.** A headless `@path` reads a file with no policy check and no `tool_use` event, so job text could pull in a local file. The escape is the CLI's own literal form. Cost: the model sees `jobs\@acme.com`, and a draft may repeat the backslash, which validation or an edit catches. The consent preview shows the wire text.
- **Decision 17's env list is now only `GEMINI_API_KEY` and `GEMINI_CLI_HOME` for Gemini.** `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` were dropped, because they could point the CLI at Vertex AI. `~/.gemini/.env` and `~/.env` can still select Vertex, which the app cannot see. `CODEX_API_KEY` is on the Codex child's allow-list although the adapter is inert.
- **The Code Assist licence path.** The register row for a Code Assist Standard or Enterprise licence sign-in is `unknown` and not built. Dropping `GOOGLE_CLOUD_PROJECT` breaks a licence sign-in that needs it: the CLI throws `ProjectIdRequiredError`, which reads as `cli_account_refused` with copy that names plans, not the project.
- **Google's note on Antigravity.** Google's docs carry a banner that Gemini CLI was replaced by Antigravity CLI on June 18th, 2026 for unpaid-tier and Google One users. Someone signed in that way may fail with an error the app reports as `cli_account_refused`, with a hint. The error class is unverified.
- **The Gemini floor has no ceiling.** Upstream was at 0.67.0-nightly while the evidence is from 0.40.0. A newer CLI is allowed and the row says it is newer than checked. The run-time guard and the smoke test are the mitigation.
- **Codex's run path, flags, and `CODEX_API_KEY` are parked.** Nothing reaches the adapter while every task needs no tools. Cost if wrong: the flags need checking before a first qualifying task.
- **`QUOTA_WORDS` changed.** `spend_limit` is out, because it matched by accident; `insufficient_quota`, `credit_balance_exhausted`, and `usage_limit` remain, and Anthropic's `enforced_spend_limit_reached` and its documented message are matched separately on the Anthropic wire. `usage_limit` has no vendor source I can name. The spend-cap words count on the Anthropic wire alone and `API_KEY_INVALID` on the Google wire alone. `QUOTA_WORDS` and the overflow words still match on the endpoint, so a hostile local server can pick a wrong reason. No data moves. A vendor spend cap reached through OpenRouter may read `http_400` or `rate_limited`, depending on whether OpenRouter forwards the words.
- **A free Gemini key can pass as a paid one.** The docs name no free-tier marker, so the attestation is the only gate. A wrong attestation sends personal data under free-tier terms. The owner accepts this.
- **macOS native TLS tops out at TLS 1.2.** If a vendor goes 1.3-only, the hosted client must move to `rustls`, which needs a real C toolchain on Windows. The `TLS handshake` step is the early warning.
- **An existing Claude consent suspends once on upgrade.** Decision 13: one `Review consent...` click, with the old categories ticked, and Rust's native confirmation behind it. Until then Claude Code stops with `consent_suspended`, and the Resumes screen says why Generate is gone.
- **The AI provider terms re-read is waived.** A changed vendor term can go unnoticed. The re-read stays for the site rows 0.5 and 0.6 rely on. No register table row or date was edited in this release, because any row edit suspends every consent record for that provider.
- A model id is typed by hand and checked against a safe character set, with no default. A mistyped id reads `model_not_found` on screen. A model id naming search, deep research, or computer use is refused.
- An off CLI that only the login shell can find (an nvm install under a GUI launch) reads "turn on to look for it" until it is enabled. Enabling runs the full search.
- A restore reads a listed provider key's value only to see that it exists, and drops it at once. A restore that changes the endpoint address drops that key.
- `PATHEXT` and `%VAR%` in a CLI shim's folder name are handled more narrowly than Windows does. A same-user threat, parked; the cost is a CLI not found.
- A picked npm `gemini.js` on Windows cannot be spawned directly. The name is accepted; it was not changed.
- A mistyped `ai keys ...` (a key typed on the command line) still echoes through the argument parser; the usage error names no argument, but the terminal shows what was typed.

## Upgrading

Open a 0.3 database with 0.4 and the app writes `backups/pre-migrate-11-<stamp>/` first, then applies migration 0012. Restoring that folder returns the 0.3 data. There is no down migration.

Your existing Claude Code consent is suspended once and needs one re-confirm: on the AI screen choose **Review consent...**, then **Allow selected**, and confirm the system dialog. Nothing else changes for you: every new provider is off until you add a key or a path, type a model id where one is needed, and consent.
