# JobPilot AI 0.2.0

Candidate and local AI. Status: not published; builds are unsigned. This is a personal, non-commercial app, and the owner waived AI subscription-policy concerns. The security controls (untrusted job text, no tools, consent records, no invented qualifications, no inferred work authorization) were not waived.

## What was built

- Candidate profile: countries, regions, cities, currencies, time zones, languages, work modes. Work authorization is stored as the user states it, per country, encrypted, and never inferred.
- Field encryption (AES-256-GCM) with a data key in the OS keychain, created at first sensitive use. Recovery-key export and import, discard of locked fields behind a `pre-discard` snapshot, and distinct key states (not loaded, unlocked, unavailable, missing, mismatched).
- Resume import from PDF and DOCX; knowledge base; pasted job texts normalized as untrusted with findings shown; resume and cover letter drafts with claim-level evidence, versions, comparison with the original, and DOCX and PDF export. A claim with no evidence, or one that states work authorization, is stored flagged and blocks export.
- Task router with three backends: Ollama on loopback (local models only; cloud models refused; hardware fit; user-started downloads; embeddings), Claude Code through the user's own `claude` login, and No-AI. Claude Code runs with `--tools "" --allowedTools StructuredOutput`, gets job text on stdin only, and needs a consent record for `claude_code/cli_login`.
- Terminal panel in the app running the bundled `jobpilot` CLI (a sidecar), with a restricted line interpreter and a launcher for the user's `claude`. Profile, Resumes, and AI views.
- Migrations 0002 to 0005. Backup, restore, export, and delete-all cover the new tables and keys. A restore also revokes external consent, audited, so a backup cannot grant it back.
- Exports land under the data root, in `exports/`: the app offers no other folder. Only the CLI's `resume export --out`, in an ordinary terminal, can write elsewhere. An export is plain text, so treat that folder as you would the data itself.
- Enabling a provider routes it, after the stored `ai.order`. The Resumes view has a Knowledge section to approve, mark, add, and remove items, so import to generate works without the terminal. README has the first-run steps.

## Outstanding risks

Ponytail ceilings and accepted limits:
- No vector index: search is brute force, fine to about 50,000 vectors.
- The recovery-key file has no passphrase. Anyone with it and a copy of the database opens every sensitive field. It must never sit in the data root or a backup.
- Resume parsing uses heading heuristics and keeps titles, employers, and dates inside bullets. Memory use of the PDF parser is unbounded; a hostile PDF could crash the app.
- Builds are unsigned (D3). Keychain access can be refused after an upgrade.
- DejaVu Sans only: CJK names print blank in PDF. Ship a NOTICE for the font before an installer goes public.
- The Claude Code adapter has no tool, but installed plugins still load, and whether their hooks run under its flags is unverified. The owner's `~/.claude/CLAUDE.md` may load beside job text.
- A paraphrase can pass the unsupported-claim and work-authorization checks (word matching, not meaning). The user's review is the last control.
- Windows credential-denied state and the real macOS denied prompt are untested; a wrong mapping could offer discard when it should offer retry.
- Claude timeout 180 s, retried once on validation failure only; a long posting falls to the next provider with `prompt_too_large`.

Deferred review items (all reviewed as minor):
- Keychain calls run under the database write lock during restore and delete-all.
- A registry/path edge: oversized `secret_index` names can block delete-all on Windows.
- `crypto` and recovery: no 0001-to-0002 migration test of its own, discard and import edge branches thinly tested, no parent-directory fsync of the recovery file.
- Profile validation is thin: country codes like `ZZ` pass, no de-duplication, unbounded chips.
- Exports: same-title drafts overwrite each other on disk; the compare view misreads lost-row and locked states; the `claims` check proves ids, not that evidence supports the sentence.
- Import normalization: quadratic worst case on hostile input, an incomplete invisible-character list, a text box or white text can read as a claim, and some authorization phrasings (for example `USCitizen`) are not caught.
- Claude adapter: a reply that quotes a login message may read as not signed in; a descendant holding stdout can stall a timeout; a relative `JOBPILOT_CLAUDE_BIN` differs between routes; login-shell lookup is uncached (up to 5 s on each status with no `claude`).
- Ollama: redirect and URL hardening untested, response size not capped, error body uncapped, overflow wording unverified on a real server.
- Terminal: no prompt reprint after Ctrl-C, no handling of a rejected ack, close blocks 250 ms.
- Desktop: `ai_status` holds the gate across `claude --version`; the GUI cannot pick a path through a symlink such as `~/.local/bin/claude` if the dialog resolves it; no download progress; a second Ctrl-C is untested.
- Tests that depend on the host: some status tests read the environment; the locked-keychain test passes when skipped; keychain tests must not run with `--release`.
- Docs and wireframes: reasons are matched by message text in `reasons.ts`; wireframe 6 delete wording and screen 14's no-compatible-model row differ from the build.
- `task_runs` is never pruned.
- The AI view picks an embeddings model by a name heuristic.

## Upgrading

Open a 0.1 database with 0.2 and the app writes `backups/pre-migrate-1-<stamp>/` first. Restoring that folder returns the 0.1 data. There is no down migration.
