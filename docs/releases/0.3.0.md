# JobPilot AI 0.3.0

Career memory, application tracking, and emergency pause. Status: not published; builds are unsigned. This is a personal, non-commercial app. The owner waived AI subscription-policy concerns. The security controls (untrusted job text, no tools, consent records, no invented qualifications, no inferred work authorization, confirmation before a sensitive answer is used) were not waived.

## What was built

- **Application tracking** (FR-2.12). Add, edit, filter, and remove applications; change status with a history; add notes. Offline. A status change runs through the tracking agent, so it appears in Agents. `jobpilot app add|list|show|history|edit|status|note|answers|remove`, and an Applications view.
- **Career memory** (FR-8.1 to FR-8.8). Questions you are asked again and again, with answers you approve, provenance, freshness (stale after 180 days), and a sensitivity class: `normal`, `sensitive`, `legal`, or `work_authorization`. Rule words set the class. A sensitive or legal answer is sealed at rest (AES-256-GCM, the same data key as the profile). Search is by meaning with a local embedding model, else by words, and never shows a sensitive answer. `jobpilot memory ...` and a Memory view.
- **Confirmation before use** (FR-8.8, M-27). A sealed answer's text comes back only after a person confirms that answer version for one application, through a native dialog in the app or `memory confirm` in an ordinary terminal. Editing the answer, changing its class, or unapproving it voids the confirmation. Confirming also marks the answer reviewed.
- **Work authorization** (M-28). Memory stores no value. A question of that class is answered from the encrypted profile row for the exact country, and a missing value reads "not stated". A question that states authorization cannot be lowered out of the class.
- **Memory refresh.** A model may double-check classes and may only raise one. One attempt per question, at most 20 per press, and only you start it. Before any Claude call the app and the CLI say how many calls it will make. Resuming a halted refresh makes none. A class you set is final: the classifier skips it.
- **Workflow runner and agents** (FR-11.10 to FR-11.16). A deterministic runner with a static permission set per agent, execution logs, checkpoints, timeouts, retries, heartbeats, and cancellation. The resume, cover letter, career memory (refresh), tracking, and analytics agents run on it. `jobpilot agents list|show|log|cancel|resume`, and an Agents view. A run whose process died is moved to `halted` with the reason `interrupted`.
- **Analytics** (FR-10.11). Counts and rates over your applications, built on request, with no model and no network. `jobpilot analytics report|show`, and a summary in the Applications view. The median response time prints with a "days" unit, and the 30-day window follows your local calendar.
- **Emergency pause** (FR-12.8, M-25). The title bar's Emergency pause button on every screen, the native Safety menu, `Ctrl/Cmd+Shift+H`, and `jobpilot pause set|status|clear`. The flag is in the database, so the app and the CLI see each other's. Each process polls it every 250 ms. It stops runs, model calls, and model pulls, survives a restart and a restore, and is audited on set and clear. Clearing asks through a native dialog. Status edits are refused with `paused`; field edits and notes stay open.
- Migrations 0006 to 0011. Schema version 11. A 0.2 database (version 5) upgrades after a `pre-migrate-5-*` snapshot.
- Two changes that touch existing behaviour: a restore that revokes external consent also turns `ai.enabled.claude_code` off, and the date a status change stamps as `applied_on` is now your local date (it was the UTC date, so it could read as tomorrow west of UTC).

## The emergency pause shortcut: read this

`wry` 0.57.1 hands `performKeyEquivalent` to the `WKWebView`. On macOS, `Cmd+Shift+H` may therefore not fire while the web process is hung, which is the case the pause exists for. The reliable paths are clicking **Safety > Emergency pause** in the menu bar, and `jobpilot pause set` from any terminal. The key works as a webview listener while the page is alive. No person pressed the menu item or the shortcut in a real window for this release (see Task 11 rows below). Windows was not looked at for the same gap.

Also: a `claude` session you start in the terminal panel is your own session and is not stopped by the pause. A `jobpilot` command run inside the panel is.

## Outstanding risks and parked items

Rulings made during the build, each a deliberate cost:

- Memory refresh is only ever started by you, so classes can stay at the rules' guess until you press it. Cost: one more click.
- A restore that revokes consent also turns Claude Code off. Cost if wrong: re-enable it.
- Revealing a sealed memory answer or a marked knowledge body asks through a native dialog each time. Cost: one extra click.
- A restore with an unreadable pause state comes up paused. Cost if wrong: one click on Clear pause.
- A question that states authorization (`able to work in <country>`, `legally able to work`) cannot be lowered out of `work_authorization`, so a harmless line such as "Visa card" can be held there. `able to work in a team`, `weekends`, and `remote` are excluded.
- Any review or confirmation can void a confirmation elsewhere. It fails closed, and the cost is an extra dialog. Revisit when 0.6 fills forms.
- A person's class is final (`class_source = 'user'`): the classifier skips it, so a class a person lowered stays low until they change it.
- Over-reported data categories in a log under two refreshes at once, because `task_runs` has no run id. The error is on the safe side.
- A lock held over 5 seconds ends the retry. The row is reaped to `halted` and stays resumable. A resume racing a status change, or a cancel racing a resume of an analytics run, can end `report_missing` or rewind a status; both are narrow, loud, and visible in history.
- A resumed analytics report can mix two moments in its figures.
- The source scan that checks every route to a status write passes the gate can be evaded by deliberate obfuscation, and the wiring of a later status writer is only caught by the full review or the runner gate.

Known limits, none fixed here:

- Rule words miss a paraphrased sensitive question, which then stays `normal` and needs no confirmation until a person sets its class. `immigration` can flag an honest resume line, and a capitalized word after `able to work in` can read as a place.
- `memory_authorization` is not gated. Browser fill in 0.6 must not reuse it.
- The clipboard is not cleared after a copy, and answer text on a CLI command line lands in shell history.
- Search falls over on an Ollama outage instead of falling back to words, vectors are never refreshed when a model changes, and duplicates are removed only when adjacent.
- There is no 0007 to 0008 backfill test and no class-lower reindex test.
- An edit cannot clear an application's link, and an update that changes nothing writes an event.
- Summary in Applications does not refresh by itself after a status change; press Refresh.
- The pause's 250 ms poll and the 2 second Agents refresh have no test of their own.
- `waiting_for_human` is in the schema and counted as active, and nothing enters it in 0.3.
- Some native dialogs name a hex id, and some name no answer id at all.
- A final whole-branch review covers Task 8's last fix round, which had no separate re-review.

## Upgrading

Open a 0.2 database with 0.3 and the app writes `backups/pre-migrate-5-<stamp>/` first. Restoring that folder returns the 0.2 data. There is no down migration.
