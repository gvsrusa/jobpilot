# JobPilot AI 0.6.0

Browser automation. Status: not published; builds are unsigned. This is a personal, non-commercial app. The security controls hold in every mode, the Claude Code apply mode included: untrusted page text; typed values must be approved facts (choices under a Normal question are not checked); no inferred work authorization; no bypass of a stop once one is detected (detection rests on word lists); logged submissions; emergency pause.

Placeholders named `PLACEHOLDER_...` are filled by the controller from a real run or a CI run. Nothing in this note was written from a run that did not happen, and a placeholder that is still there means the run did not happen yet.

## What was built

- **The browser runtime** (decision 22). `@playwright/mcp` 0.0.84, which depends on exactly `playwright` `1.65.0-alpha-2026-10-30`, is pinned by `crates/core/assets/browser-runtime/package.json` and a committed lockfile. Nothing is bundled: `jobpilot browser setup` (or Set up browser on the run screen) runs the owner's own Node 20 or later and npm (`npm ci --ignore-scripts`), then downloads Chromium into `<root>/browser-runtime`. `jobpilot browser status` reads `no_node`, `node_too_old`, `not_installed`, `wrong_version`, or `ready`. Rust drives the server as an MCP client over stdio; there is no Rust Playwright crate and no injected JavaScript.
- **The browser itself** (M-35). Chromium, visible, with a fresh profile per run at `<root>/apply/<id>/profile`, deleted at the end. No user profile, no cookies between runs, downloads off, page tools off. No anti-detection: the server's `AutomationControlled` flag is turned off with a value that disables nothing (decision 9), and `navigator.webdriver` stays true. Egress is not limited by the network layer (decision 11).
- **A permissions engine** (`permissions`, M-36). It decides each action (open link, supply, drive, fill, upload, submit) by mode, site, the build-time register row, a verified list, and a person's grant, and refuses by default. Fixture sites on `127.0.0.1` exist only in debug builds.
- **Manual mode**, on every site. The review screen shows the four modes with Rust's fixed reasons, the files, the approved answers, and work authorization as stated or not. Rust opens an https link in the default browser and copies an answer to the clipboard (a sealed one only after a native confirmation), clearing it after 60 s. `Record outcome` tracks the application. CLI: `jobpilot apply material`, `apply record`.
- **Copilot mode**, on Greenhouse, Lever, and Ashby hosted forms under decision D2, recorded as "no clause found" on the run. It parses the accessibility snapshot, maps fields by rules (FR-3.22), asks the new `map_form_field` task about at most 20 fields it could not map (the model sees candidate questions and ids, never an answer's text), fills, uploads the two files, and stops at a review step where the person clicks submit. It clicks no button itself, only a landing link named exactly `apply`, `apply now`, or `apply for this job`. It pauses off the posting's origin. Refused on Workday, Indeed, and LinkedIn with no process started. CLI: `jobpilot apply copilot`.
- **The Autonomous gate** (decision 24). `permissions::VERIFIED` is empty, so no site is eligible. The run path, `jobpilot apply autonomous run <application>` and Tauri `autonomous_start`, is refused while no site is eligible, with no run row, no browser, and no dialog. Behind the gate: one submit click per application (an application with any earlier submission, in any mode, is refused `already_submitted` by Copilot, Autonomous, and Claude Code apply until its outcome is recorded), a fresh page compare before it, doubt ends `uncertain`, and no model call. Grants: `apply autonomous list|grant|revoke`.
- **The Claude Code apply mode**, by the owner's decision of 2026-11-01 ([policy register](../policy-register.md#owner-decision-2026-11-01-claude-code-apply-mode-release-06)). It works on all sites, including Indeed, LinkedIn, and Workday, and submits with no per-application check once the owner starts a run. The owner selects up to 25 saved applications with an https link and presses `Apply with Claude Code...` (CLI: `jobpilot apply preflight`, `apply start [--release-sealed]`). The preflight renders each resume and letter through the claim guards and shows the blocks; one native dialog asks whether to release the sealed answers and work-authorization values to this run. The terminal panel then runs `jobpilot apply session <id>`, which starts the owner's own `claude` as its child.
  - **Two walls on tools.** `claude` gets `--tools ToolSearch`, one MCP server under `--strict-mcp-config`, `--allowedTools mcp__jobpilot__*`, and `dontAsk`, with settings sources, slash commands, hooks, `CLAUDE.md`, and auto memory off. The session keeps one built-in, `ToolSearch`, which loads tool schemas and nothing else; Claude Code 2.1.317 needs it to reach MCP tools in an interactive session, where `--tools ""` left them unreachable (found in the first real session). The fixed system prompt is a file, `--system-prompt-file <run>/system-prompt.txt`, that `prepare` writes into the run folder and that goes with it: a `claude.cmd` passes arguments through cmd.exe, which turns line breaks into spaces (found in the first Windows CI run). On Windows every child (`claude`, `apply-mcp`'s Playwright server, the terminal panel) also gets a fixed list of system variables (`SystemRoot`, `SystemDrive`, `windir`, `TEMP`, `TMP`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `PATHEXT`, `ComSpec`); macOS and Linux children get nothing new. Its one server is JobPilot's `apply-mcp` proxy, which lists 3 apply tools (`apply_next`, `apply_pause`, `apply_result`) and 13 browser tools, refuses every other name, and runs the Playwright server as its own child.
  - **Facts only, two files only.** `apply_next` gives one application's facts at a time. Every typed value must be an approved answer or profile fact, checked in Rust; work authorization needs the stated value for the application's exact country; a field whose label the rules class as legal is refused. Before each application the proxy stages only that application's `resume.pdf` and `cover-letter.pdf`, and an upload must be one of the two.
  - **Stops.** The proxy snapshots after each action and scans every snapshot for sign-in, CAPTCHA, MFA, identity checks, legal declarations, and alert dialogs. A hit holds the tool reply until a person continues, in the pause panel or with `jobpilot apply resolve`. The model can open a stop and cannot end one. A stop holds 30 minutes, then the application is handed to the person and the run goes on. A second submit click on one application stops too.
  - **Logged and tracked.** Rust counts submit clicks from its own snapshot. `apply_result` reports the outcome; Rust captures the page's claim, writes an audit row, a note, and the status through the tracking agent. A submission with no observed click, or a doubt, reads `uncertain`: "Check the site. JobPilot will not try again." A question with no answer goes to career memory as an unapproved form question.
  - **Emergency pause** kills `claude`, `apply-mcp`, the Playwright server, and Chromium within 2 s, on the desktop path or the CLI path, by sweeping every process whose arguments name the run folder. The run ends `halted` and does not resume; the owner starts a new run. After a crash, the next desktop start, apply start, `apply status`, `apply show`, run screen, or Manual record sweeps orphans and settles their items; until the owner looks, the processes, the profile, and the transcript stay. A session whose host died refuses its next browser call once the host's agent run is halted or its heartbeat is 30 s old, and the desktop ends a run whose hosted session exits on its own. A status read or a Manual record starts `claude purge` and does not wait for it.
  - At the end, `claude purge` is run on the session folder. Task 14 checked it twice on the real Claude Code 2.1.317: no transcript folder was left and no `purge_failed` row was written. A failure is logged `purge_failed` and leaves the transcript.
- **Screens.** Application review (wireframe 11, four modes), the Claude Code apply run (wireframe 19: Setup needed, Preflight, Running, Ended), the pause panel, and the terminal panel's `Claude Code apply run` header.
- **Fixtures.** 17 synthetic forms in `crates/core/tests/fixtures/forms/`: Greenhouse-, Lever-, Ashby-, Workday-, Indeed-, and LinkedIn-shaped pages with invented names and no brand asset, one per mandatory stop, a stop that shows only after a click, a two-page form, and hostile, fake-success, and reject-once pages.
- Migrations 0016 (`apply_runs`, `apply_items`, `apply_pauses`, `autonomous_grants`) and 0017 (`apply_items.released_answers`). Schema version 17. Version 0.6.0.

## Known issues

- **Panel table wording.** The 0.6 plan's panel table calls `apply preflight` read only. It writes: it renders each application's resume and letter PDFs under `exports/apply/<application>/` and adds an `export` audit row, because export is the only path with every claim guard. Nothing cleans those folders but delete-all.
- **Node wording.** The plan said Node 18; the floor is 20, the strictest `engines.node` in the lock. A Node that does not answer `--version` reads "Node unknown is too old". `browser status` runs `node --version` each time.
- **Closing the panel mid-run** ends the apply PTY but does not sweep the run folder at once. The browser lasts until the host's wind-up or the next startup sweep. Emergency pause and Cancel run sweep at once. A run whose host the panel killed reads `running` until the heartbeat goes stale or the owner presses Cancel run.
- **`in_use` during a wind-up.** After a pause, the desktop keeps a database handle while it winds up a dead host's run, which can include a `claude purge` of up to 30 s. A restore or delete-all in that window is refused with `in_use`; retry it.
- **A close before the host writes its record** makes the next claim wait for the sweep, up to 30 s.
- **Clipboard on macOS.** A copied answer is marked concealed and cleared after 60 s. A clipboard history tool that ignores the concealed type keeps it.
- **One unexplained e2e flake.** `browser_e2e_emergency_pause_closes_the_browser_and_deletes_the_profile` failed once in development and not in 9 runs after. A Chromium helper started between the sweep and its kill is the suspected cause; the later sweep catches it.
- **Copilot.** The opener click and the review text are not in the original brief. A Copilot run holds the AI slot for the whole run, so other AI tasks wait.
- **Autonomous.** It matches controls by role and name, not by ref, and ends the item for the person (`manual_required`) on any choice it cannot read back, any ambiguous control, or a page with a legal declaration or identity request. No site is eligible, so none of this runs outside tests.
- **Purge.** After the real runs no transcript folder was left under `~/.claude/projects` and no `purge_failed` row was written. A failure is logged `purge_failed` with the folder and leaves the transcript.
- Parked lows from the reviews: a malformed same-id MCP reply is skipped with no call timeout of its own; a cancel polls every 50 ms; child output of `browser setup` is discarded, so a failure reports only `npm_ci_failed` or `chromium_failed`; `exports/apply` is never cleaned; a form question's text, and the application's company, role, and link, are not marked as data in the brief (threat model, section 11); a release keys on the answer id, not its version; an exit between a claim and its write can lose a status, which `apply settle` recovers.

## Outstanding risks and parked items

- **The owner's decision.** The Claude Code apply mode works on sites whose terms bar automated applying (Indeed, LinkedIn) or may (Workday). A site may restrict or ban the account used. The owner accepted this on 2026-11-01. The register keeps the vendors' verdicts as the record, and Manual, Copilot, and Autonomous still follow them.
- **Pause detection rests on word lists.** A stop worded outside them, in another language, with lookalike letters, or split across inline elements, is missed, and the session goes on with no per-application check.
- **Choices outside classified labels are not value-checked**, and a steered session can still put a true approved answer in the wrong field, or a released sealed value on a hostile page.
- **A submit is counted only on a control named to submit.** The proxy counts and guards a click only on a button or link whose name holds `submit`, `send application`, or `finish application`. A submit by Enter, or by a final button named "Apply", "Continue", or "Done", reads `uncertain`, and the owner checks the site. A second click on such a button is neither counted nor paused, so a double submission on such a form is possible. The proxy does not check that the fields are filled before a submit click: in apply mode the session decides when the form is complete.
- **The transcript** of an interactive session holds released values until `claude purge` runs.
- **The pin is an alpha** (`playwright` `1.65.0-alpha-2026-10-30`), and Node, npm, and Chromium downloads are trusted at setup, with lockfile hashes for the npm packages only.
- **Guard residuals**, each a deliberate cost: a page-controlled group name; a question after its options or more than 8 lines away; non-English questions; a sensitive option missing from `SENSITIVE_OPTIONS`; legal words split across inline children; Cyrillic lookalikes; Greenhouse's default sponsorship question always pausing; a `role=listbox` inside a `<label for>`; an option `value` attribute that lies; an unnamed native `select` refused `unlabeled_field`; a form-bearing page dialog skipping the generic Other stop; a URL slug with a stop word pausing once; an escaped quote in a typed answer pausing; a page-prefilled value equal to a typed one skipped by the scan; a confirm dialog the session accepts with `browser_handle_dialog` after a person continued its Legal stop, with no guard of its own; yes and no toggle buttons outside an option group, where the second button has no question and passes; offscreen or opacity-0 controls that still get refs, so a decoy control can exempt a blocking dialog from the generic Other stop; a question beyond the choice's field boundary (another field or a button between them) not found. See the [threat model](../security/threat-model.md#11-residual-risks).
- **Timeouts include holds** (decision 19): 8 hours for a Claude Code apply run, 2 hours for a Copilot or Autonomous run, holds included.

## Upgrading

Open a 0.5 database with 0.6 and the app writes `backups/pre-migrate-15-<stamp>/` first, then applies migrations 0016 and 0017. Restoring that folder returns the 0.5 data. There is no down migration. The new tables start empty.

No AI consent changes: the policy register's AI provider rows were not edited, so no consent record is suspended. A Claude Code apply run needs an active Claude Code consent covering `job_text`, `profile_basic`, and `career_memory`, and `sensitive` to release sealed answers; Copilot's model step needs `job_text` and `career_memory`. Without it the run is refused with `consent_required`, or Copilot leaves the fields to you.

Nothing downloads until you run `jobpilot browser setup` or press Set up browser. It needs Node 20 or later on this computer. Nothing opens a browser until you start a run.
